# Barge-In Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a wake word heard while mia is speaking interrupt her mid-sentence (barge-in), instead of being ignored the way all speech is today during `SPEAKING`.

**Architecture:** `start_speaking()` moves to fire right before audio playback actually begins (after Claude dispatch + TTS synthesis complete), rather than immediately after a command is captured — so `SPEAKING` precisely means "audio is playing," not "processing or playing." STT keeps flowing to Deepgram during `SPEAKING` so the wake-word matcher can hear an interruption; hearing the wake word during `SPEAKING` now transitions back to `LISTENING` and stops the audio. Playback becomes non-blocking (`sounddevice` is already asynchronous under the hood) so the main loop keeps running while audio plays, instead of blocking until it finishes.

**Tech Stack:** Python, `sounddevice` (already a project dependency).

## Global Constraints

- Barge-in is wake-word-gated only — no "any speech interrupts" mode. This was explicitly decided after directly considering and rejecting the alternative (see the design spec's "Why wake-word-gated, not any-speech" section).
- `COMMAND_CAPTURED` (Claude dispatch + TTS synthesis in flight) stays non-interruptible. There is no audio playing yet to interrupt during that window, and canceling an in-flight Claude API call is explicitly out of scope.
- Interrupting a response never undoes the underlying action or its conversational-memory record — both already happened before playback started. Barge-in only stops how long mia keeps talking about it.
- Scoped to the currently-implemented `sounddevice`-based playback path (`main.py`'s BlackHole output and `demo_standalone.py`'s default-device output). The not-yet-built Attendee/live-Meet integration is out of scope.

        before or during synthesis (nothing to play). Skips SPEAKING/COOLDOWN

```python
import numpy as np
import sounddevice as sd


def start_playback(
    pcm_audio: bytes, device_name: str = "BlackHole 2ch", sample_rate: int = 16000
) -> None:
    """Start playing raw PCM 16-bit audio out through the named output
    device. Does not block -- sounddevice plays asynchronously under the
    hood, which is what lets the caller keep running its own loop (reading
    mic frames, watching for a barge-in wake word) while audio plays."""
    samples = np.frombuffer(pcm_audio, dtype="int16")
    sd.play(samples, samplerate=sample_rate, device=device_name, blocking=False)


def is_playback_active() -> bool:
    """True while audio started by start_playback() is still playing."""
    stream = sd.get_stream()
    return stream is not None and stream.active


def stop_playback() -> None:
    """Immediately stop whatever start_playback() is currently playing.
    A harmless no-op if nothing is playing."""
    sd.stop()
```
